# CSV Schemas

CSV files use UTF-8 encoding, a header row, and LF line endings. IDs are
zero-padded strings. Generated timestamps, coordinates, RTTs, and weights use
six decimal places.

## `input/peers.csv`

| Column | Type | Meaning |
|---|---|---|
| `peer_id` | string | Unique peer identifier. |
| `initial_x`, `initial_y` | float | Two-dimensional position at `t=0`. |
| `movement_model` | enum | `static` or `random_walk`. |
| `movement_speed` | float | World units per second. |

## `input/entities.csv`

| Column | Type | Meaning |
|---|---|---|
| `entity_id` | string | Unique entity identifier. |
| `initial_x`, `initial_y` | float | Fixed two-dimensional position. |
| `initial_authority` | peer ID | Single authority at the start of replay. |
| `state_size_bytes` | integer | Abstract amount of state transferred per migration. |

## `input/network.csv`

| Column | Type | Meaning |
|---|---|---|
| `src_peer` | peer ID | Source peer. |
| `dst_peer` | peer ID | Destination peer. |
| `rtt_ms` | float | Fixed round-trip time in milliseconds; zero for self communication. |

All ordered peer pairs are present, allowing direct matrix lookup.

## `input/peer_positions.csv`

| Column | Type | Meaning |
|---|---|---|
| `timestamp` | seconds | Sample time, including `t=0`. |
| `peer_id` | peer ID | Peer represented by this sample. |
| `x`, `y` | float | Position at the sample time. |

Random walks advance every `simulation.timestep`, but positions are recorded
every `peers.position_sample_interval`. Static peers have only one sample, at
`t=0`. The supplied replay uses the most recent sample at or before a request
time (hold-last-value), rather than interpolating positions.

## `input/interactions.csv`

| Column | Type | Meaning |
|---|---|---|
| `timestamp` | seconds | Request time, with `0 <= t < duration`. |
| `request_id` | string | Identifier unique within the dataset. |
| `entity_id` | entity ID | Target shared entity. |
| `peer_id` | peer ID | Requesting peer. |
| `request_type` | string | Type defined in `request_types.csv`. |

Interaction weights are stored separately so that weight sensitivity can be
studied without regenerating the request sequence.

## `input/request_types.csv`

| Column | Type | Meaning |
|---|---|---|
| `request_type` | string | Type name used to join with `interactions.csv`. |
| `interaction_weight` | float | Configured weight; its interpretation is a policy parameter. |

Changing weights does not require changing `interactions.csv`. If input files
are edited manually, the manifest checksums and effective configuration no longer
describe those edited inputs; retain the original dataset for regeneration checks.

## Replay outputs

`output/<policy_id>/results.csv` and optional `decisions.csv` are generated by
`nve_policy`; they are not generator inputs. See
[Policy evaluation](POLICY_EVALUATION.md) for their fields and cost equations.
